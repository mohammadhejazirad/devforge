# راهنمای DevForge

این راهنما برای کسی است که می‌خواهد ابزارهای توسعه را روی لینوکس نصب و مدیریت کند. خود برنامه فقط انگلیسی حرف می‌زند، چون بیشتر ترمینال‌ها فارسی را درست نشان نمی‌دهند. متن دستورها و پیام‌ها انگلیسی است.

نسخهٔ این درخت **1.3.0** است. نصب یک‌خطی همان نسخه را از انتشار گیت‌هاب می‌گیرد و مدیریت ابزارها و منوی ترمینال در آن هست.

## نصب از مخزن

```bash
git clone https://github.com/mohammadhejazirad/devforge.git
cd devforge
python3 -m devforge --help
```

اگر بخواهید دستور `devforge` در همه‌جا باشد:

```bash
python3 -m pip install --user -e .
devforge --version
```

باید `devforge 1.3.0` را ببینید. پایتون ۳.۹ یا جدیدتر کافی است و برای اجرای خود برنامه بستهٔ اضافه‌ای لازم نیست.

## نصب منتشرشده

```bash
curl -fsSL https://raw.githubusercontent.com/mohammadhejazirad/devforge/main/install.sh | bash
```

این دستور فایل `devforge-1.3.0.tar.gz` را از انتشار گیت‌هاب می‌گیرد، SHA256 را با مقدار داخل `install.sh` مقایسه می‌کند و در `~/.local` نصب می‌کند. اسکریپت دیگری از اینترنت اجرا نمی‌شود. نصب دوباره فقط فایل‌های خود برنامه را عوض می‌کند و ابزارهای نصب‌شده را پاک نمی‌کند. اگر هنوز نسخهٔ 1.0.0 را دارید، یک بار دیگر `install.sh` را اجرا کنید. از 1.1.0 به بعد `devforge self-update` نسخهٔ جدیدتر را می‌گیرد.

## چه چیزهایی را مدیریت می‌کند

زبان‌ها: PHP، Node.js، Go، Python، Rust، Java، Ruby، .NET، Bun، Deno.

ابزارهای بسته: NVM، npm، pnpm، Yarn، Composer، pipx، uv، pyenv.

زیرساخت: Docker و Compose، Git، kubectl، Helm، Terraform.

سرویس‌ها: MySQL، MariaDB، PostgreSQL، Redis، Nginx، Caddy.

ابزارهای روزمره: ابزار ساخت، curl، jq، tmux، ripgrep، OpenSSH.

برای هر کدام می‌توانید ببینید چه نسخه‌ای نصب است، نسخهٔ جدید هست یا نه، و اگر امن باشد نصب، به‌روزرسانی، تعویض پیش‌فرض، سنجاق کردن روی پروژه، حذف، و بررسی انجام دهید.

دو مدل نصب وجود دارد:

- آرشیو رسمی (مثل Node و Go) کنار هم در `~/.local/share/devforge/tools` می‌ماند. نصب نسخهٔ تازه، نسخهٔ قبلی را پاک نمی‌کند. یک shim به PATH اضافه می‌شود.
- بستهٔ توزیع (مثل PHP و Python و پایگاه داده) با apt یا dnf یا pacman یا zypper یا apk نصب می‌شود. `install php` بستهٔ پیش‌فرض توزیع را می‌گیرد. `install php 8.4` روی دبیان `php8.4-cli` و روی آلپاین `php84` را می‌خواهد. اگر آن خانواده نتواند نسخهٔ درخواستی را انتخاب کند، برنامه نصب نسخه‌ای متفاوت را به‌جای موفقیت گزارش نمی‌کند و طرح متوقف می‌شود. بستهٔ نسخه‌دار باید در مخازن تنظیم‌شدهٔ سیستم موجود باشد.

`/usr/bin/python3` عوض نمی‌شود. NVM و pyenv اگر باشند دست نمی‌خورند و نصب‌کنندهٔ اینترنتی آن‌ها اجرا نمی‌شود. npm همان npm خود Node است. Rust با فایل رسمی `rustup-init` و بعد از بررسی checksum نصب می‌شود، مگر اینکه rustup از قبل داشته باشید. دات‌نت فقط از مخزن خود توزیع نصب می‌شود. روی دبیان و آلپاین، که SDK در مخزن پیش‌فرض نیست، برنامه مخزن مایکروسافت اضافه نمی‌کند و همان‌جا متوقف می‌شود.

## دستورهای روزمره

پرچم‌های سراسری قبل از نام دستور می‌آیند. هر تغییر اول طرح را نشان می‌دهد. `--dry-run` فقط طرح را چاپ می‌کند. `-y` پرسش تأیید را برمی‌دارد. `--json` خروجی ماشینی می‌دهد.

```bash
devforge info
devforge doctor --offline
devforge list
devforge status
devforge status php
devforge versions node
devforge --dry-run install node
devforge install php 8.4
devforge use node 24.22.1
devforge pin python 3.13
devforge update php
devforge update --all
devforge uninstall node 22.23.4
devforge shell install
devforge
devforge self-update
```

`status php` نسخهٔ نصب‌شده، منبع آن (`system` یا `devforge`)، تازه‌ترین نسخهٔ شناخته‌شده، و کارهایی که ممکن است را نشان می‌دهد: نصب، به‌روزرسانی، تعویض، حذف. اگر PHP نباشد می‌گوید نصب نیست. `update php` اگر نباشد نصب می‌کند، اگر بستهٔ جدیدتر در توزیع باشد ارتقا می‌دهد، و اگر جدیدتر نباشد می‌گوید از قبل به‌روز است. `update` بدون نام ابزار باید با `--all` باشد و `--all` فقط ابزارهایی را که واقعاً نصب شده‌اند بررسی می‌کند.

`use` پیش‌فرض را برای کاربر عوض می‌کند. `pin` و `use --project` فایلی مثل `.php-version` و یک خط در `.tool-versions` داخل پوشهٔ جاری می‌نویسند. `use --shell` فقط یک `export` چاپ می‌کند و چیزی ذخیره نمی‌کند.

`doctor` ابزار غایب را هشدار می‌دهد. اگر نسخهٔ انتخاب‌شدهٔ DevForge روی دیسک نباشد با کد ۱ خارج می‌شود. بررسی شبکه فقط با `devforge doctor --online` است.

`export` فهرست JSON ابزارهای نصب‌شده را چاپ می‌کند. `apply` همان فایل را دوباره نصب می‌کند. این شکل TOML هم قبول است:

```toml
[tool.node]
version = "24.22.1"
default = true

[tool.git]
```

پیش‌تنظیم‌ها:

| نام | محتوا |
| --- | --- |
| `web-php` | php، composer، node، nginx، git، curl |
| `node-fullstack` | node، pnpm، git، curl |
| `go-backend` | go، git، docker |
| `devops` | docker، kubectl، helm، terraform، git، jq |

اگر یکی از ابزارهای یک پیش‌تنظیم قابل نصب نباشد، کل طرح متوقف می‌شود.

در زیرمنوی PHP گزینهٔ **Install PHP extensions** افزونه‌ها را دسته‌بندی نشان می‌دهد. بسته‌ها دقیقاً برای نسخهٔ نصب‌شده هستند: اگر PHP 8.5.12 باشد، نام‌ها `php8.5-*` است. Enter همه را نصب می‌کند و این انتخاب پیش‌فرض است. Enter داخل یک دسته فقط همان دسته را نصب می‌کند.

اگر در ترمینال فقط `devforge` را بزنید، رابط Textual باز می‌شود. منوی شماره‌ای قبلی با `devforge tui --plain` در دسترس است و کارهای عمومی آن شامل این موارد است: رایانه، doctor، پیش‌تنظیم، آینه، DNS، پوسته، و به‌روزرسانی خود DevForge. اگر نسخهٔ جدید روی گیت‌هاب باشد، همان صفحهٔ اول می‌گوید. بدون ترمینال، یا وقتی فقط فلگ داده باشید، راهنما چاپ می‌شود و کد خروج ۲ است. `devforge tui` همان منو را باز می‌کند. `devforge self-update` آرشیو انتشار را با SHA256 بررسی می‌کند و فقط خود برنامه را عوض می‌کند. کپی مخزن گیت را بازنویسی نمی‌کند؛ آن را با `git pull` به‌روز کنید.

## نسخهٔ شناخته‌شده

`install node` خط LTS را انتخاب می‌کند، یعنی 24.22.1. `update node` آخرین انتشار پایدار در همان شاخهٔ اصلی را کنار نسخهٔ فعلی نصب می‌کند؛ مثلاً 22 به 24 تغییر نمی‌کند. برای تغییر شاخه `install node 24` را اجرا کنید. نصب بدون نسخه و با نسخهٔ کوتاه، و آپدیت آرشیوها، در حالت آنلاین فهرست رسمی را خودکار تازه می‌کنند؛ dry-run از فهرست موجود استفاده می‌کند. `install node 26.12.1` همان نسخه را کنار نسخه‌های دیگر می‌گذارد. فهرست‌ها با `devforge versions node --refresh` از منبع اصلی تازه می‌شوند. چک‌سام‌های سنجاق‌شده مربوط به تاریخ ۲۰۲۶-۱۰-۲۳ هستند.

اگر چک‌سام در فهرست نباشد، موقع اجرا از فایل چک‌سام ناشر خوانده می‌شود. بدون چک‌سام چیزی نصب نمی‌شود. در طرح خشک این موضوع نوشته می‌شود.

دانلود Go از `go.dev` به CDN گوگل می‌رود و در بعضی شبکه‌ها 404 برمی‌گرداند. این به معنی نبودن نسخه نیست. خطا را می‌بینید و می‌توانید بعد از انتخاب آینه دوباره تلاش کنید. برنامه آینهٔ ساختگی اضافه نمی‌کند.

## آینه و DNS

هر دو خاموش‌اند تا خودتان بخواهید. پیش‌فرض همان نشانی اصلی است و بررسی checksum باقی می‌ماند.

```bash
devforge mirror list
devforge mirror set iran
devforge mirror test
devforge mirror reset
devforge dns show
devforge dns set cloudflare
devforge dns test
devforge dns restore
```

نمایهٔ `iran` تأیید نشده است. فقط می‌تواند آینهٔ رجیستری داکر را به `/etc/docker/daemon.json` اضافه کند و قبلش پشتیبان می‌گیرد. مخزن apt یا npm یا PyPI را عوض نمی‌کند. `mirror reset` انتخاب را پاک می‌کند و اگر پشتیبان `daemon.json.devforge.bak` باشد آن را برمی‌گرداند.

برای DNS، کلودفلر و گوگل تأییدشده‌اند. شکن، الکترو، بگذر و 403 پیشنهادهای تأییدنشدهٔ جامعه هستند. نشانی `10.x` فقط روی شبکه‌ای کار می‌کند که به آن مسیر داشته باشد. برنامه systemd-resolved یا NetworkManager یا resolvconf یا فایل ثابت را تشخیص می‌دهد، پشتیبان می‌گیرد، و `dns restore` پشتیبان را برمی‌گرداند. اگر نام رابط یا اتصال پیدا نشود، طرح متوقف می‌شود و می‌گوید خودتان چه کار کنید.

## ایمنی

- قبل از تغییر، دستور دقیق نشان داده می‌شود. کار ریشه با `sudo --` و دلیلش مشخص است.
- اولین ویرایش هر فایل پیکربندی در `*.devforge.bak` می‌ماند.
- حذف فقط داخل پوشه‌های خود DevForge مجاز است.
- رشتهٔ نسخه قبل از استفاده در مسیر یا دستور بررسی می‌شود.
- دستورها با پوسته ساخته نمی‌شوند.
- داده‌ای به جایی فرستاده نمی‌شود.
- بلوک پوسته در `.bashrc` یا `.zshrc` یا فایل fish علامت دارد و `devforge shell remove` فقط همان بلوک را برمی‌دارد.

کد خروج: ۰ موفق، ۱ طرح مسدود یا خطا یا انصراف، ۲ استفادهٔ نادرست.

## مسیرها

| کاربرد | مسیر |
| --- | --- |
| ابزارها و shimها | `~/.local/share/devforge` |
| لاگ | `~/.local/state/devforge/logs/devforge.log` |
| پیکربندی | `~/.config/devforge/config.json` |
| حافظهٔ موقت | `~/.cache/devforge` |

متغیرهای `XDG_*` این مسیرها را عوض می‌کنند. لاگ رمز و توکن را خط می‌زند.

## تفاوت آپدیت و تغییر نسخه

`update php` شاخهٔ major.minor نصب‌شده را حفظ می‌کند: برای نمونه، 8.5.1
می‌تواند به 8.5.3 برسد، ولی به 8.6 نمی‌رود. Python و Go نیز major.minor
را حفظ می‌کنند؛ Node و دیگر ابزارهای آرشیوی شاخهٔ major را حفظ می‌کنند.
برای تغییر شاخه از `install` و برای انتخاب نسخهٔ نصب‌شده از `use` استفاده کنید.

آپدیت PHP ابتدا فهرست بسته‌های سیستم را تازه می‌کند و اصلاحات امنیتی با
شمارهٔ بازبینی متفاوت را هم نصب می‌کند. مقصد، آخرین بستهٔ مخازن تنظیم‌شدهٔ
توزیع است؛ اگر آخرین انتشار php.net در آن مخزن نباشد، دریافت آن تضمین نمی‌شود.
در خروجی JSON، `update_target` مقصد همان شاخه و `new_release_available` وجود
شاخهٔ جدیدتر را جدا نشان می‌دهند.

نصب npm در صورت نبودن Node آن را نصب می‌کند. Composer نیز PHP و Yarn نیز
Node را در طرح نصب خود می‌آورند. آپدیت npm به همان major محدود است. Rust
کانال فعال stable را آپدیت می‌کند؛ ابزارزنجیرهٔ سنجاق‌شده باید صریح انتخاب شود.

نصب‌کننده انتشار 1.3.0 را با اصلاحات آپدیت همان شاخه، استخراج Node و نصب
وابستگی‌های اصلی دریافت می‌کند. برای ارتقای نسخه‌های قبلی `devforge self-update`
را اجرا کنید. ابزارهای نصب‌شده حفظ می‌شوند.
